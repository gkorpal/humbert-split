# humbert-split

## Data

Polarization datasets live under `data/`, generated by
[`scripts/polz_random.jl`](scripts/polz_random.jl) and
[`scripts/polz_all.jl`](scripts/polz_all.jl). Each file opens with a short header
(the prime `p`, the order basis) followed by one polarization per line.

| Directory | Naming | Contents |
| --- | --- | --- |
| `polz_small_all/` | `polarizations_p<p>.txt` | Small primes, complete enumerations |
| `polz_small_100k/` | `polarizations_p<p>.txt` | Small primes (up to p = 1619), 100k samples |
| `polz_big_10k/` | `polz_<bits>bit_<digest>_10000.txt` | 50–1000 bit primes, 10k samples |
| `polz_big_100k/` | `polz_<bits>bit_<digest>_100000.txt` | 50–1000 bit primes, 100k samples — **stored split, see below** |

Primes under 25 bits are named by their decimal value; larger ones by bit length
plus an 8-hex-digit digest of `p`, since a 1000-bit prime has ~302 digits and
cannot go in a filename. The convention is implemented in
`default_output_filename` in [`scripts/polz_random.jl`](scripts/polz_random.jl).

### Reassembling `polz_big_100k/`

That directory is 3.8 GB, with individual files up to 317 MB — over GitHub's
100 MB per-blob limit. Each file is therefore stored as a sequence of
line-aligned pieces of at most 90 MB:

```
polz_1000bit_faa1c19f_100000.txt.part00
polz_1000bit_faa1c19f_100000.txt.part01
polz_1000bit_faa1c19f_100000.txt.part02
polz_1000bit_faa1c19f_100000.txt.part03
```

The pieces are plain uncompressed text, so rebuilding is just `cat`. After
cloning:

```bash
cd data/polz_big_100k
./merge.sh              # all 20 files (~3.8 GB of output)
./merge.sh 1000bit      # or just the ones matching a substring
```

No dependencies beyond coreutils. `merge.sh` checks each rebuilt file against
`SHA256SUMS`, so the result is guaranteed byte-for-byte identical to the
original. It is safe to re-run — files already merged are skipped. Make sure you
have ~3.8 GB free.

The merged `.txt` are gitignored, so they will not appear as local changes.

Because the pieces are split on line boundaries, each one is also a valid
standalone fragment you can inspect or `grep` without merging anything.

### Re-splitting (maintainers)

After adding or regenerating files in `data/polz_big_100k/`:

```bash
cd data/polz_big_100k
for f in *.txt; do split -C 90M -d -a 2 "$f" "$f.part"; done
sha256sum *.txt > SHA256SUMS
```

Then confirm nothing exceeds the limit — this must print nothing:

```bash
find data/polz_big_100k -name '*.part??' -size +100000000c
```

Commit the pieces and `SHA256SUMS`; never the `.txt`.
